# AGENTS.md

## 1. What this is

This is a **scaffolded fullstack monorepo**, not the template itself. It was
generated by `bun create <org>/forge <name>` and personalised by
`bun run setup` (which rewrites the `@yourorg/*` package scope, project name,
and generates real local secrets). If any of that still looks unrun, run
`bun run setup` once before anything else below. Bun workspaces tie six
packages together: two apps that ship (API, web), two mobile targets, and two
shared libraries.

## 2. Repo layout

- `apps/api` — Hono HTTP API: security middleware, trace-id propagation, a
  single `onError` boundary, argon2id + JWT auth seam, Prisma-backed example CRUD.
- `apps/web` — Vite + React 19 + Tailwind v4 + shadcn/ui SPA.
- `apps/mobile` — Expo app; resolves workspace packages via a custom Metro
  `resolveRequest`.
- `apps/mobile-lynx` — **EXPERIMENTAL** ReactLynx target (rspeedy). Safe to
  delete wholesale with `rm -rf apps/mobile-lynx` if you don't need it.
- `packages/shared` — cross-cutting error taxonomy (`AppError`, `ErrorCode`,
  `getUserMessage`).
- `packages/lib` — small framework-agnostic helpers (calendar-date math).

## 3. How to run things

```
docker compose up -d
bun install
bun run db:generate
bun run db:migrate
bun run --filter '@yourorg/api' dev
bun run --filter '@yourorg/web' dev
bun run --workspaces --if-present typecheck
bun run lint
bun test
```

`docker compose up -d` starts Postgres, API, and web. Postgres is published on
host port 5433, API on 3000, and web on 8080. Run the Prisma migration commands
above before tests or direct API startup. Replace `@yourorg` with your
personalised scope once `bun run setup` has run. There is no root `test` script
— Bun's test runner needs none; `bun test` from the repo root recursively
discovers every `*.test.ts` across every workspace. Run it scoped to one package
instead if you only want that package's suite, e.g. `cd apps/api && bun test`.

The web Docker container writes `/config.js` at startup from runtime `API_URL`
(default `http://localhost:3000`). For k3s, set `API_URL` from a ConfigMap; it is
public browser config, not a Secret.

## 4. Module boundaries

`apps/web`'s `.oxlintrc.json` enforces import boundaries via
`eslint-plugin-boundaries`, checked by `bun run lint`, not by convention:
each directory under `apps/web/src/modules/` (e.g. `apps/web/src/modules/example`)
is a `module`-type element, importable from outside only through its own
`index.ts` — reaching into a module's internal files (e.g.
`apps/web/src/modules/_fixture-b/internal`) from another module fails lint.
`apps/web/src/lib` (`shared`) and `apps/web/src/components` (`ui`) are
importable from anywhere. This is a real, enforced rule, not documentation —
violating it fails CI via `bun run lint`.

## 5. Error handling convention

Every error surfaced to a client has the shape
`{code, message, traceId, details?}`. `packages/shared/src/errors` defines
`AppError` (a namespaced `code` like `auth/UNAUTHENTICATED`, optional
`details`, optional HTTP `status`) and `getUserMessage(code)`, which resolves
a stable, localisable, user-facing string per code. `apps/api/src/error/on-error.ts`
is the **one and only place** that constructs an HTTP error response: it logs
full detail server-side, but an unrecognised error never leaks its message or
stack to the client — only `common/INTERNAL_ERROR`. Add new codes in a
per-module errors file (e.g. `apps/api/src/modules/auth/auth.errors.ts`),
namespaced module-slash-code, like the existing `auth/UNAUTHENTICATED`.

## 6. Auth

`apps/api/src/modules/auth` implements register/login/me/logout: argon2id
password hashing (`Bun.password`), a single short-lived (<= 15 min) JWT
issued as an httpOnly cookie, no user enumeration, and its own stricter
rate-limit bucket. **There is no refresh token in v1** — logout is
best-effort (cookie deletion only, nothing to revoke server-side) and a
token stays valid until it naturally expires. The store backing all of this
(`apps/api/src/modules/auth/user-store.ts`) is an **in-memory `Map`** — it
resets on every restart. Wire real persistence before using this beyond a
demo. Details: `apps/api/src/modules/auth/README.md`.

## 7. Known limitations / what to do next

- No refresh token; re-auth after expiry is a full login (see §6).
- Auth store is in-memory, not a database — the first real task on a new
  project is usually wiring Postgres here.
- `apps/api/src/modules/example` is a Prisma-backed demo CRUD module, meant to
  be deleted with its migration or replaced by real domain modules.
- `apps/mobile-lynx` is experimental and unrelated to the Expo app; delete
  it if unused.
- `docker-compose.yml` runs Postgres, API, and web — no Redis, no queue, no other
  service is wired yet.
- CSRF relies on `SameSite=Lax` + a CORS allowlist, not a dedicated
  CSRF-token scheme (see the auth README's "CSRF stance" section).
