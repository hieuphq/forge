# AGENTS.md

## 1. What this is

This is a **scaffolded fullstack monorepo**, not the template itself. It was
generated by `bun create <org>/forge <name>` and personalised by
`bun run setup` (which rewrites the `@yourorg/*` package scope, project name,
and generates real local secrets). If any of that still looks unrun, run
`bun run setup` once before anything else below.

## 2. Repo layout

- `apps/api` — Hono HTTP API: security middleware, trace-id propagation, a
  single `onError` boundary, argon2id + JWT auth, Prisma-backed users/roles and auth routes.
- `apps/web` — Vite + React 19 + Tailwind v4 + shadcn/ui SPA with runtime
  `/config.js` API URL configuration.
- `apps/mobile` — Expo app; resolves workspace packages via a custom Metro
  `resolveRequest`.
- `apps/mobile-lynx` — **EXPERIMENTAL** ReactLynx target (rspeedy). Safe to
  delete wholesale with `rm -rf apps/mobile-lynx` if you don't need it.
- `packages/shared` — cross-cutting error taxonomy (`AppError`, `ErrorCode`,
  `getUserMessage`).
- `packages/lib` — small framework-agnostic helpers (calendar-date math).
- `deploy/k3s` — minimal Kubernetes scaffold for API, web, Postgres, ingress,
  ConfigMap, Secret example, and migrate Job.

## 3. How to run things

```
docker compose up -d postgres
bun install
bun run db:generate
bun run db:migrate
bun run db:seed
bun run --filter '@yourorg/api' dev
bun run --filter '@yourorg/web' dev
bun run --workspaces --if-present typecheck
bun run lint
bun test
```

`docker compose up -d postgres` starts local Postgres on host port 5433. The API
runtime image is slim and does not run migrations at container startup; run
`bun run db:migrate` locally or use the k3s migrate Job before starting API pods.
There is no root `test` script — Bun's test runner needs none; `bun test` from
the repo root recursively discovers every `*.test.ts` across workspaces.

## 4. Module boundaries

`apps/web`'s `.oxlintrc.json` enforces import boundaries via
`eslint-plugin-boundaries`, checked by `bun run lint`, not by convention.
`apps/web/src/lib` (`shared`) and `apps/web/src/components` (`ui`) are
importable from anywhere.

## 5. Error handling convention

Every error surfaced to a client has the shape
`{code, message, traceId, details?}`. `packages/shared/src/errors` defines
`AppError` and `getUserMessage(code)`. `apps/api/src/error/on-error.ts` is the
one and only place that constructs an HTTP error response.

## 6. Auth

`apps/api/src/modules/auth` implements register/login/me/logout, owner-only user
management, argon2id password hashing (`Bun.password`), a single short-lived
(<= 15 min) JWT issued as an httpOnly cookie, no user enumeration, and stricter
auth rate limiting. Users are stored in Postgres through Prisma.

## 7. Docker/k3s runtime config

- API image: full Bun build stage, slim Bun runtime stage.
- Migration image: separate Bun image with Prisma CLI for `db:migrate`.
- Web image: Vite build served by Nginx; `/config.js` is generated at startup
  from runtime `API_URL`.
- In k3s, `API_URL` belongs in a ConfigMap because it is public browser config.
  Secrets are only for server-side values like DB password, JWT secret, and S3
  keys.

## 8. Known limitations / what to do next

- No refresh token; re-auth after expiry is a full login.
- Add your real domain modules after replacing or extending the auth-only scaffold.
- `apps/mobile-lynx` is experimental and unrelated to the Expo app; delete it if
  unused.
- `docker-compose.yml` runs Postgres/API/web only — no Redis, no queue, no other
  service is wired yet.
- CSRF relies on `SameSite=Lax` + a CORS allowlist, not a dedicated CSRF-token
  scheme.
